# esun-etf-agent

AI CUP 2026 玉山人工智慧公開挑戰賽「Agent 基金經理人：打造你的最佳 ETF 投資組合」。

## 每日 Agent 流程

```
第 D 日收盤後
  1. python scripts/agent_daily.py prepare
       更新資料（日 K、法人、月營收、重大訊息）→ 以 D 日價格結算前一次委託 → 量化評分
       → runs/<D+1>/context.md
  2. Claude（排程 session，依 docs/daily_agent_playbook.md）
       讀 context、重大訊息、TradingView 新聞與總經行事曆 → 寫 runs/<D+1>/decision.json
  3. python scripts/agent_daily.py finalize
       驗證並套用 decision → 整張下單 → 壓力測試 → 合規檢查
       → orders.csv（交易書）、report.md（決策報告）、target_holdings.csv
```

- **LLM 的權限有上限。** 只能調整風險水位（投入 88–98.5%）、加減碼 0.5–1.5 倍（最多 8 檔）、剔除最多 5 檔、從候選名單加入最多 3 檔，而且每一項都要附理由。超出範圍的項目會被修正或丟棄並記錄警告。
- **自動退回。** 沒有 decision.json 或格式錯誤時，退回量化基準組合，照樣產出交易書。
- **壓力測試。** 假設隔日開盤全面上漲 3%，買進金額仍不能超過現金。
- **稽核紀錄。** 每個交易日的 `runs/<日期>/` 保存 context、decision、驗證結果、交易書、報告、成交結果，以及含雜湊值的 `log.jsonl`。
- **帳本。** 存在 `state/ledger.json`。平台公布實際持股後，可用 `reconcile` 指令覆蓋。
- **演練。** `--dry-run` 會寫到 `dryrun/`，不影響正式紀錄。
- **資料健康檢查。** 價格不是最新交易日時，`prepare` 直接停止，不會用舊資料下單；法人、月營收、重大訊息如果落後，會在 context 與報告最上方警告。
- **集中度診斷。** context 與報告列出產業權重、高度相關的股票，以及「相當於幾個獨立部位」，避免以為分散、其實同一注下了很多次。

量化基準（`strategies/composite.py`）：動能、近 3 個月營收年增率、外資與投信淨買超三個因子加權評分；台積電固定 22%，其他 24 檔等權重，同產業最多 6 檔。已持有的股票只要排名還在前 40 名就續抱，以降低換手。

## 快速開始

```bash
pip install -r requirements.txt
python scripts/update_data.py                    # 標的池 + 日 K + 官方收盤價抽查（約 1 分鐘）
python scripts/update_data.py --finmind all      # 加上法人、月營收、股利、本益比（沒有 token 約 2 小時）
python -m pytest                                 # 單元測試
python scripts/run_backtest.py --windows --strategy cap_weighted,equal_weight,momentum --start 2022-01-01
```

FinMind 免費註冊後把 token 設在環境變數 `FINMIND_TOKEN`，下載速度快一倍。

## 已實作的比賽規則（`rules.py`）

| 規則 | 值 |
|---|---|
| 起始資金 | 10 億 |
| 持股檔數 | 20–30 |
| 權重上限 | 2330 為 25%，其他個股 10% |
| 現金 | 低於淨值 25%，不能為負（不可融資） |
| 交易單位 | 整張（1000 股） |
| 成本 | 手續費 0.1425%（買賣都收）；賣出另收證交稅 0.3% |

## 回測假設

- **時間軸：** 第 t 日的決策只用 t-1 日收盤以前的資料，以 t 日開盤價成交（`--exec-price close` 可改成收盤價成交），以 t 日收盤價估值。
- **可交易條件：** 當天成交量大於 0 才能交易。停牌、面額變更、下市的股票不能買賣，但仍計入持股檔數。
- **下單：** 每檔無條件捨去到整張，現金不足時從買最多的那檔開始一張一張減；取整後多出的現金再一張一張補給低配最多的股票。
- **權重緩衝：** 上限再預留 0.5%（`DEFAULT_CAP_BUFFER`），吸收手續費和價格跳動。
- **股利：** 除息日把現金股利記入現金；配股以整張近似。
- **月營收：** 視為次月 11 日才公開。

## 待向主辦單位確認（會影響回測設定）

1. 成交價基準是開盤價、收盤價、均價，還是其他價格？每天幾點截止提交？
2. 權重上限是只在下單時檢查，還是每天收盤都檢查？如果每天收盤都算，台積電漲多了就會被動超標。
3. 除權息是否計入組合市值？配股怎麼處理？
4. 漲跌停鎖死時能不能成交？
5. 官方標的池清單，以及決策報告、交易書的格式。

## 已處理的資料問題

- **yfinance 整天缺漏或塞佔位資料：** 例如 2021-04-06、2025-08-01 全市場缺漏，2024-03 上櫃有 4 天成交量全為 0。用官方交易日曆偵測，再改抓 TWSE/TPEx 單日行情取代。
- **個股歷史缺漏：** 例如 5371 在 yfinance 只有 1 筆，改用 FinMind。這檔 2026-08-21 之後就沒有交易。
- **停牌期間仍有價格：** 例如 2327 國巨在 2025-08 因面額變更停牌，透過成交量為 0 判斷為不可交易。
- **抽查：** 每次更新後，最新交易日的收盤價都和官方比對。

## 基準結果（暫定標的池、開盤價成交、band 1%）

### 2022-01 ~ 2026-10，228 個 24 日視窗

| | 市值加權 | 等權重 | 動能 |
|---|---|---|---|
| 平均報酬 | 2.00% | 1.60% | 4.36% |
| 平均超額（vs 0050 含息） | -0.76% | -1.16% | +1.60% |
| 贏 0050 的比例 | 34% | 38% | 57% |
| 平均交易成本 | 0.22% | 0.33% | 1.33% |
| 第 10 百分位報酬 | -5.80% | -5.68% | -7.77% |

### 2026-08 之後（標的池選出之後，沒有前視偏差），31 個重疊視窗

| | 市值加權 | 等權重 | 動能 |
|---|---|---|---|
| 平均超額 | -1.36% | -2.10% | +0.37% |
| 贏 0050 的比例 | 6% | 10% | 52% |

**解讀時要注意：**

- **倖存者偏差：** 標的池是 2026 年 7 月的大型股，拿它回測 2022 年等於事先知道誰會變大，動能策略的成績因此被高估。沒有偏差的只有 2026-08 之後的視窗，但只有約 2.5 段互不重疊的區間，樣本太小。
- **台積電上限的影響：** 0050 裡台積電占 5–6 成，這裡最多 25%。只要台積電大漲，所有隊伍都會輸 0050，但大家受同樣的限制。比賽排名是隊伍之間的比較，0050 只是參考線。
- **交易成本：** 動能策略每 24 天約 600% 換手、成本 1.3%，吃掉大部分超額報酬。降低換手是最直接的改善方向。

### 量化基準（composite）參數比較（2022-01 ~ 2026-10，228 個視窗；尚未納入法人因子）

| 設定 | 平均超額 | 贏 0050 比例 | 平均成本 | 有違規的視窗 |
|---|---|---|---|---|
| 台積電 24% | +1.61% | 58% | 0.33% | 20（台積電收盤漂移） |
| **台積電 22%（預設）** | **+1.69%** | **58%** | **0.33%** | **0** |
| 台積電不特別處理 | +2.21% | 59% | 0.40% | 0 |
| 持股 20 檔 | +1.65% | 59% | 0.30% | 30 |
| 持股 30 檔 | +1.67% | 60% | 0.38% | 13 |

### 法人因子（外資 + 投信 20 日淨買超）

| | 加法人（預設） | 不加法人 |
|---|---|---|
| 2022 至今：平均超額 | +1.79% | +1.87% |
| 2022 至今：超額中位數 | +1.13% | +1.03% |
| 2022 至今：最差回撤 | -28.6% | -30.5% |
| 2026-08 之後：平均超額 | -1.11% | -1.98% |
| 2026-08 之後：贏 0050 比例 | 16% | 19% |

全期間幾乎沒有差別；2026-08 之後加法人比較好，但只有約 2.5 段獨立期間，證據很弱。保留的理由是全期間不扣分，而且決策報告比較容易解釋。
**沒有倖存者偏差的近期，量化基準大多輸給 0050**，所以全期間的超額報酬有一部分來自偏差。

### 同產業檔數上限（台積電另計）

| | 不設上限 | **6 檔（預設）** | 4 檔 |
|---|---|---|---|
| 2022 至今：平均超額 | +1.79% | +1.84% | +1.64% |
| 2022 至今：第 10／90 百分位報酬 | -6.9% / 18.0% | -6.8% / 17.6% | -6.7% / 16.1% |
| 2022 至今：成本 | 0.39% | 0.42% | 0.50% |
| 2026-08 之後：平均超額 | -1.11% | -0.76% | -0.94% |

6 檔在兩個期間都不比不設上限差，採用的理由是風險控制：績效沒有損失，又能避免單一產業塞得太滿。

各設定的差異都在雜訊範圍內。遲滯機制讓成本從純動能的 1.33% 降到 0.33%，超額報酬則和純動能差不多。
「台積電不特別處理」表面上最好，但這主要來自動能選股，而動能正是受倖存者偏差影響最大的部分，所以沒有採用。

## 資料源

- **TradingView：** 對台股大型股的新聞很即時，中小型股的新聞很少、常常過期；分析師目標價的單位有誤，台股的財報日程是空的。所以只用在總經行事曆，和台積電與權值股的新聞。
- **重大訊息：** 公開資訊觀測站的 OpenAPI 只提供最近一個交易日，所以 `prepare` 每天累積一次（存在 `data/announcements.parquet`）。
